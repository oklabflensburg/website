# Dependency compatibility

Use Node >=22.22.0 and **pnpm 12.3.4**, as pinned in `package.json`. `pnpm-lock.yaml` is generated by pnpm and must support `pnpm install --frozen-lockfile`. CI checks peers immediately after the frozen install.

## Issue #12: causes and scoped corrections

Verified on 2026-09-10 with `pnpm why cac oxc-parser unplugin unctx @bomb.sh/tab` and published npm package manifests.

| Top-level dependency chain | Mismatch | Resolution |
| --- | --- | --- |
| `nuxt@4.5.2` → `@nuxt/cli@3.37.0` → `@bomb.sh/tab@0.0.19` | Tab's optional `cac` peer only accepts `^6.7.14`, while the tool graph provides `7.0.0` | Use upstream Tab `0.0.22`, whose peer range supports cac 6 and 7 |
| `@nuxt/content@3.16.0` → `nuxt-component-meta@0.18.0` → `@nuxt/kit@4.5.2` → `unctx@3.0.1` | component-meta provides `oxc-parser@0.139.0` and `unplugin@2.3.11`, but unctx 3 requires `>=0.140.0` and `^3.3.0` respectively | Resolve only component-meta's Kit dependency to `4.4.8` (within its declared `^4.4.8`), which uses compatible `unctx@2.5.0` |

The overrides in `pnpm-workspace.yaml` select both the exact parent version and its affected child. They install real published compatible package versions. They do not replace peer metadata, suppress warnings, force a global parser/unplugin downgrade or change the application's Nuxt version.

### Why these overrides

- The latest published Nuxt CLI checked was `3.37.0`; it still requests Tab `^0.0.19`. For a `0.0.x` package, that range excludes `0.0.22`, so an ordinary compatible lockfile update cannot select the fix. [Upstream PR #149](https://github.com/bombshell-dev/tab/pull/149) widens the cac range. Tab `0.0.22` was published on 2026-08-04.
- The latest Content/component-meta versions checked were `3.16.0`/`0.18.0`; component-meta still declares the older parser and unplugin ranges alongside Kit `^4.4.8`. A global unctx downgrade would violate current Nuxt's requirements; upgrading component-meta's parser and unplugin beyond their ranges would require two less conservative overrides. Its scoped Kit pin respects the package's own declared range. Kit `4.4.8` was published on 2026-06-08.
- A Content downgrade was considered: `3.15.0` uses component-meta `0.17.2`. It would also discard unrelated [Content 3.16 fixes](https://github.com/nuxt/content/releases/tag/v3.16.0), including stable async ContentRenderer identity and build/runtime corrections. Keeping current Content and narrowing the affected dependency edge is the smaller runtime change.
- Adding unrelated root peer-provider dependencies solely to manipulate resolution would obscure ownership. The corrections stay at the two responsible dependency edges instead.

pnpm's parent-to-child override selectors are documented in [dependency resolution settings](https://pnpm.io/settings#overrides).

### Removal criteria

1. Remove `@nuxt/cli@3.37.0>@bomb.sh/tab` when Nuxt CLI accepts a Tab release supporting cac 7.
2. Remove `nuxt-component-meta@0.18.0>@nuxt/kit` when component-meta's parser/unplugin ranges support the peers required by current Kit/unctx.
3. Re-resolve with pnpm, inspect the lockfile, and rerun peers plus the full application checks. Exact parent-version selectors deliberately stop applying when those parents upgrade; the CI peer check detects unresolved upstream incompatibilities.

## Supply-chain and lockfile policy

- Keep `packageManager: pnpm@12.3.4`.
- Retain pnpm's release-age protection and the pre-existing exact `zod@4.6.1` exception; no new age exception is added. Both corrected versions predate the release-age window.
- Keep the existing `allowBuilds` entries for `esbuild` and `unrs-resolver`; no extra lifecycle scripts are approved.
- Preserve peer checking and frozen installs. No `peerDependencyRules`, ignored peers, broad overrides or install hooks are introduced.
- Lockfile regeneration also deduplicates the two MCP tooling packages' Zod resolution from `4.5.4` to the already approved and installed `4.6.1`; it adds no new top-level dependency or policy exception.

## Validation

Required commands: `pnpm install --frozen-lockfile`, `pnpm peers check`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`, `pnpm test:e2e`. Review desktop/mobile screenshots and the generated asset diff. GitHub Actions is disabled at repository level as checked on 2026-09-10; local validation must not be presented as remote CI success.
